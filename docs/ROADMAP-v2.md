# AGenUI ROADMAP v2

> 更新日期：2026-08-27
> 基于：PROJECT-STATUS-v3.md

经过 Phase 1-4 + 20 轮自迭代，AGenUI 已完成 Bitmap 渲染桥接、10 模板体系、LLM 意图识别、缓存优化等核心能力。下一阶段聚焦端侧智能化、多实例、跨端协同。

---

## 一、下一阶段方向

### 方向 1：端侧推理（优先级 P0）

**目标**：在设备端完成意图识别 + 模板选择，消除云端 LLM 依赖，实现零延迟响应。

| 子项 | 描述 | 优先级 |
|------|------|--------|
| TFLite 意图分类模型 | 训练轻量意图分类模型（10 类模板），导出 TFLite，集成到 Widget 模块 | P0 |
| 本地实体提取 | 基于规则 + 词典的 NLU 实体提取（时间/地点/人名/数字），替代云端 NLU | P0 |
| 端云混合策略 | 简单意图走端侧（<50ms），复杂生成走云端 LLM，用户无感切换 | P1 |
| 模型动态下发 | 通过资产包下发/更新端侧模型，无需 App 升级 | P2 |

**验收标准**：
- 端侧意图识别准确率 ≥ 90%（10 类模板）
- 端侧响应延迟 ≤ 50ms
- 离线场景下 10 模板可正常切换

---

### 方向 2：多 Widget 实例（优先级 P1）

**目标**：支持桌面同时存在多个 AGenUI Widget（如天气 + 待办 + 议程），独立配置、独立渲染、独立刷新。

| 子项 | 描述 | 优先级 |
|------|------|--------|
| 多实例 Surface 管理 | SurfaceManager 支持多 surfaceId 并发，独立 measure/draw | P1 |
| 实例配置 UI | Widget 配置 Activity，支持选择模板 + 自定义数据 | P1 |
| Bitmap 缓存隔离 | 缓存 key 按 appWidgetId 隔离，避免串扰 | P1 |
| 调度优先级 | 多实例刷新时按 Widget 可见性排序，前台优先 | P2 |

**验收标准**：
- 桌面同时存在 ≥ 3 个 AGenUI Widget，互不干扰
- 每个 Widget 独立配置模板和数据
- 切换桌面时全部 Widget 正确恢复

---

### 方向 3：跨设备同步（优先级 P2）

**目标**：用户在一台设备配置的 Widget 模板/数据，自动同步到其他设备（手机/平板/大屏）。

| 子项 | 描述 | 优先级 |
|------|------|--------|
| 云端配置存储 | 用户 Widget 配置（模板 + 数据）上传云端，基于 OpenID 账号体系 | P2 |
| 增量同步协议 | 基于 timestamp + diff 的增量同步，节省流量 | P2 |
| 多设备适配 | 同一模板在不同屏幕尺寸（手机/平板/大屏）自适应布局 | P3 |
| 离线冲突合并 | 离线编辑冲突时基于 last-write-wins + 手动合并 UI | P3 |

**验收标准**：
- 设备 A 配置天气 Widget → 设备 B 10s 内同步显示
- 弱网下配置不丢失，恢复后自动补同步
- 三种屏幕尺寸下模板布局自适应

---

### 方向 4：AI 助手集成（优先级 P2）

**目标**：与系统级 AI 助手（如小艺、Google Assistant）打通，通过语音指令直接操作 Widget。

| 子项 | 描述 | 优先级 |
|------|------|--------|
| 语音 Intent 对接 | 注册系统 VoiceIntent，支持 "给待办加一项买菜" 等自然语言指令 | P2 |
| 上下文感知 | AI 助手感知当前 Widget 状态，支持 "切换到下周视图" 等上下文操作 | P2 |
| 跨 Widget 联动 | "把今天的会议加到待办" — 从 meeting 提取 action items 写入 todo | P3 |
| 主动建议 | 基于时间和位置，主动建议切换模板（如会议前 5 分钟自动切到 meeting） | P3 |

**验收标准**：
- 唤醒 AI 助手后说出指令，Widget 正确响应
- 跨 Widget 数据流转正确（meeting → todo）
- 主动建议不打扰用户，可通过设置关闭

---

## 二、优先级排序总览

| 优先级 | 方向 | 理由 |
|--------|------|------|
| **P0** | 端侧推理 | 消除云端依赖是离线可用 + 低延迟的基础，其他方向都依赖它 |
| **P1** | 多 Widget 实例 | 用户强需求，当前单实例是主要体验瓶颈 |
| **P2** | 跨设备同步 | 提升多设备用户粘性，依赖云端基建 |
| **P2** | AI 助手集成 | 差异化能力，依赖系统级 AI 助手开放能力 |
| **P3** | 多设备适配 / 主动建议 / 跨 Widget 联动 | 锦上添花，依赖前面方向落地 |

---

## 三、技术风险

| 风险 | 等级 | 缓解方案 |
|------|------|----------|
| 端侧模型体积过大 | 中 | 量化压缩 + 动态下发，目标 <5MB |
| 多实例内存压力 | 中 | LruCache 按实例分配预算 + 可见性淘汰 |
| 云同步隐私合规 | 高 | 严格遵循数据最小化原则，敏感数据端侧加密 |
| AI 助手开放能力不确定 | 中 | 抽象 VoiceIntent 层，适配多助手（小艺/Google Assistant） |

---

## 四、里程碑规划

| 里程碑 | 周期 | 交付 |
|--------|------|------|
| M1: 端侧推理 MVP | 下一阶段 | TFLite 意图分类 + 本地 NLU，10 模板离线可用 |
| M2: 多实例 | M1 后 | 3+ Widget 实例同屏，独立配置 |
| M3: 云同步 | M2 后 | 跨设备配置同步，10s 内一致性 |
| M4: AI 助手 | M3 后 | 语音指令操作 Widget，跨 Widget 联动 |

---

## 五、与 v1 ROADMAP 的差异

v1 ROADMAP（ITERATION-PLAN-v2）聚焦"从 0 到 1"——建立 Bitmap 渲染链路、模板体系、LLM 集成、缓存优化。
v2 ROADMAP 聚焦"从 1 到 N"——端侧化、多实例、跨端协同、AI 生态集成。
